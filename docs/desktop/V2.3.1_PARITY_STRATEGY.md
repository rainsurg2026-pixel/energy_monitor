# v2.3.1 golden parity strategy

The Phase 1 parity contract is `desktop-v2.3.1`. Tests compare pure domain
outputs to machine-readable JSON expected values. All fixtures are sanitized
and deterministic; no workbook is opened, saved, recalculated, or modified by
the parity test.

Coverage includes:

- Rangsit default Energy/Cost, UPS, Air, DC and chart transformations.
- Srinakarin configured profile and phase aggregation.
- Site Comparison month union/common reference and missing-site null behavior.
- Rack Capacity status/zone ratios and Rack Unit Capacity previous-row/usage.
- null/blank/zero semantics, duplicate-month rejection, malformed/missing
  dependency behavior, month boundaries and leap-year days.

Expected floating-point results use exact equality for the v2.3.1 fixture
values. The suite has no blanket tolerance. A tolerance is allowed only for a
future fixture whose expected value cannot be represented exactly, and must be
declared per assertion with its reason.

## Regression rule

When a strange result is observed, the expected output is updated only after
confirming it is the current Desktop behavior. The test then records it as
preserved technical debt. Phase 1 does not improve formulas, change workbook
ownership, introduce PostgreSQL/Auth, or redesign charts.
