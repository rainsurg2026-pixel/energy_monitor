# Preserved v2.3.1 calculation debt

These items are intentionally preserved and are not Phase 1 fixes:

- `normalizedMonth` accepts a numeric prefix after the month token (for
  example, a malformed suffix can still normalize). This is existing behavior
  and is covered by the date parity case.
- Energy Cost requires exactly one current month record and exactly one
  previous month record for air energy. Duplicate or missing records produce
  null-derived values rather than choosing a row.
- UPS group aggregation treats missing `loadKw`/`loadKva` as zero, while the
  Energy Cost calculation treats missing group members as null. The two rules
  are different Desktop contracts and are not unified silently.
- Engineering Dashboard detail numerics use zero fallbacks for missing display
  values. This is not promoted as a future data-source rule.
- Facility Comparison prefers persisted floor-cost/rate values when present;
  Energy Cost itself always recomputes from raw building inputs. The persisted
  values are retained as parity evidence until migration policy explicitly
  resolves this discrepancy.
- There are separate regression/forecast implementations in `analytics.ts`
  and `capacityForecast.ts`. Phase 1 does not merge their APIs because that
  could change forecast results.

Each item needs an explicit product/formula decision before a future release
may alter it.
